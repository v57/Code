# CodeLuaModel

## Purpose

CodeLuaModel is a model of a Lua project built from its source text, on
[CodeModel](CodeSwiftModel.md#codemodel-the-core) and [CodeScan](CodeScan.md)'s tokens. It doesn't run Lua, LuaRocks
or a language server. In milliseconds it answers:

- where a name is defined: exact, a few candidates, or unknown;
- what can be completed at a position;
- where a definition is referenced;
- what a symbol is.

It reads the `.lua` files under a folder, the files a `require` reaches outside it, and Lua's standard library from a
hand-written stub. Lua 5.1 to 5.4 and LuaJIT read the same; `.luau` stays with the scanner.

It is not an interpreter. Lua has no declared types, so the model follows the values it can be sure of: a table
constructor, a local or global assigned from one, what `require` returns, `setmetatable`'s classes. Otherwise it gives
candidates or nothing, since an unknown answer is better than a wrong exact one. It never downloads or installs
anything.

It is Lua's model in the middle of Code's three tiers (CodeKit's `CodeTiers`):

1. CodeScan guesses first.
2. The model answers for `.lua` files.
3. A language server would be asked only when the model isn't sure, but CodeLSP's catalog has none for Lua yet
   (lua-language-server would be the one), so CodeScan's own server stands in.

Names resolve the way Lua binds them:

- **Files** (`LuaLayout`). Every `.lua` file under the root is its own module (hidden folders, `node_modules`,
  `lua_modules` and `.luarocks` left out). `require("a.b")` is found as `package.path` would find it from the root:
  `.luarc.json`'s (or `.luarc.jsonc`'s) `runtime.path` patterns, then `?.lua`, `?/init.lua` and the same under `lua/`
  and `src/`, a rockspec's `build.modules`, `workspace.library` folders and a local LuaRocks tree; then from the
  requiring file's folder up to the root, as a Factorio mod or a script run from its own folder sees it. `__mod__/x`
  names a Factorio mod's folder. A file outside the root is read when a require reaches it.
- **Syntax** (`LuaSyntax`, a recursive-descent parser of Lua 5.4's grammar). It keeps going after junk, but an
  assignment right after skipped text declares nothing unless it starts its own line, so a file that is a fragment
  doesn't make up globals.
- **Locals**: `local`, `local function` (its name seen in its own body), parameters, `...`, `for` variables,
  `local x <const>`/`<close>`, by Lua's scoping. A local is seen from the statement after its declaration, `repeat …
  until` sees the block's locals, and shadowing and upvalues are followed. `goto L` answers the visible `::L::`.
- **Globals**: a free name answers every place the program assigns it (`x = …`, `function x()`), from any file. When
  the program never assigns it, a standard library name answers the stub's. A host's globals (Factorio's `game` and
  `data`, LÖVE's `love`, Neovim's `vim`) are unknown unless the program assigns them.
- **Fields**: `e.f`, `e:f`, `e["f"]` and `{f = …}` follow `e`'s value:
  - a table constructor, a local or global assigned from one, a field holding one, `require("literal")` (the module's
    returned table), a function's returned table, `self` in `function T:m()` (what `T` names);
  - `setmetatable(t, mt)`: the fields of `t`, then along `mt.__index` (a table, or `mt` itself when `mt.__index = mt`),
    up to 8 levels: Lua's classes;
  - a string's methods are `string`'s (`s:upper()`, `("%d"):rep(2)`).
  A field answers every place it is assigned on that table, from any file (`T.f = …`, `function T.f()`,
  `function T:f()`, `self.f = …`, `{f = …}`). Fields assigned on what can't be told answer the fields of that name,
  as candidates.
- **Annotations** (LuaLS's, `---@`): `---@class Name: Parent` binds the statement right below it (a class with no
  statement is its `---@field`s alone, which pass on their types); `---@type`, `---@param` and `---@return` give a value
  a class when its own value can't be told. The value comes first: an annotation never overrides a table the code
  builds.
- **Places** (`place(of:)`), as the bench's reference names them: a path relative to the root and a line. The stub's
  are `std:<name>` or `std:<lib>.<name>`.

**Unknown on purpose**: a host's API (`game.players[1].name`), a table indexed by a computed key (`t[k]`), a value
built by a function that fills a map from computed keys or copies a table (`util.table.deepcopy`), a `require` of a
computed name, `load`, `setfenv` and `_ENV` tricks, `__index` functions, and fields on a value whose table can't be
told.

**Lua's standard library**: `LuaStd`, a hand-written stub (marked as Code's stub at the top) of Lua 5.1 to 5.4's base
library, `string`, `table`, `math`, `io`, `os`, `coroutine`, `debug`, `package`, `utf8`, `bit32` and LuaJIT's `bit`,
declarations only, with LuaLS annotations for their types. It is generated by
`../Demos/CodeModelBench/lua/tools/gen_std.py` from `tools/std.lua`, read as the module `lua` and written to
`$TMPDIR/code-lua-std/` when a file of it is opened.

**The lexer** (CodeScan's Lua rules): long strings and comments with levels (`[==[ … ]==]`, `--[[ … ]]`), `\z` in a
string skipping the whitespace after it, line breaks too, Lua's operators split as Lua reads them (`//`, `~=`, `..`,
`::`, `#`, never `=#`), and `1.` a number.

## Getting started

```swift
.package(url: "https://github.com/v57/Code.git", branch: "main"),
// in the target:
.product(name: "CodeLuaModel", package: "Code"),
```

CodeLuaModel re-exports CodeModel. The target builds in Swift 5 language mode, and the model isn't thread-safe: give
it its own serial queue.

```swift
import CodeLuaModel

let model = LuaModel(root: "/path/to/project")
let file = "/path/to/project/src/main.lua"
let answer = model.answer(path: file, line: 24, character: 6)  // from 0, UTF-16
for site in answer.sites {
  if let place = model.place(of: site) { print(place.path, place.line) }
}
model.project.update(path: file, text: editedText)  // the editor's text, after an edit
let list = model.complete(path: file, line: 24, character: 6, limit: 40)
print(list.context, list.items.map(\.label))
```

## Main API

`LuaModel` is a `LanguageModel` (CodeModel), so it is asked as the other models are.

### Loading a project

`LuaModel(root:)` reads the root's `.luarc.json`, `.luacheckrc` and rockspecs and lists its `.lua` files; a file is
parsed when a question needs it. `LuaModel(project:)` takes a `Project` whose layout is a `LuaLayout`. `project` is
CodeModel's `Project`. After an edit the tables built from the edited file are taken out and put back, in file order,
so the rest of the project isn't read again.

### Definitions and references

- `answer(path:line:character:)`, `location(of:)` (the stub's file is written out first), `place(of:)`.
- `references(of:)`: where an answer's definitions are used in the project, one line each: every use that answers the
  same definitions (a field's uses on the same table, a local's in its scope).

### Completion

`complete(path:line:character:limit:)` returns a `ModelCompletionList`:

- **After `.` or `:`**: the value's fields: its own, its metatable's class's, along `__index`, an annotated class's
  `---@field`s and its parents'; a string's are `string`'s; a function's with snippet parameters (`self` left out after
  `:`). A value whose table can't be told gives nothing, marked unknown.
- **After `local`, `local function`, `for`, in a function's parameters, after `goto` and `::`**: nothing, since a new
  name (or a label) goes there. Nothing in comments and strings.
- **Elsewhere**: the locals in scope (`self` in a method), the globals the program assigns, the standard library's, a
  host's from `.luarc.json`'s `diagnostics.globals`, and keywords.

### Symbol details

`details(of:)` returns `SymbolDetails`:

- the declaration on its line (`function Dog:fetch()`, `local count: number`);
- the description above it (`---` or `--` lines, up to the first `---@` tag);
- its file;
- a value's type, as LuaLS writes it (`string`, `table`, a `---@class`'s name, `fun(): Point`), with the class's place.

### ModelLanguage.lua

`ModelLanguage.lua` holds, for CodeKit and `code-model`:

- the extension: `lua`;
- the manifests: `.luarc.json`, `.luarc.jsonc`, `.luacheckrc`, `*.rockspec`, `stylua.toml`, `.stylua.toml`;
- how to make the model.

### The code-model tool

```bash
swift run code-model query --root ~/Projects/game --language lua --queries reference.json --out answers.json
swift run code-model complete --root ~/Projects/game --language lua --at src/main.lua:24:6
swift run code-model tokens --all --root ~/Projects/game --language lua   # CodeScan's names, for lua/tools/lexcheck.py
```

## Numbers

From `../Demos/CodeModelBench/lua` (2026-11-17, release build). No Lua interpreter, LuaRocks or lua-language-server is
on this Mac and nothing was downloaded, so **the reference is the bench's own**: `lua/tools/luaref.py`, a resolver
written apart from the model with its own lexer and parser. It names only what Lua makes unambiguous from the source
and leaves the rest out of the score. The corpora are Lua already on this Mac: the Biter Battles scenario (139 files,
43,869 lines), Factorio's own data (2,078 files, 262,232 lines), a small Factorio mod, and three fixtures written for
the bench.

- **Tuned on** Biter Battles' maps, commands and modules (34,300 positions, 26,625 with a reference): 100% exactly
  right, none wrong; references 100% recall, 99.7% precision.
- **Held out**, every identifier, scored once before looking:

  | Corpus | First run | After fixes | References recall / precision |
  |---|---|---|---|
  | Biter Battles' `utils` and `comfy_panel` (24,655 with a reference) | 100% right | 100% | 99.8% / 99.6% |
  | Factorio's data (254,172 with a reference) | 99.9% right, 247 wrong, 103 unknown | 100% | 100% / 100% (100 files) |
  | fulgora-start-fixes (134) | 100% right | 100% | 100% / 100% |

  The first run's misses on Factorio's data were CodeScan reading `1.` as `1` and `.`, fragment files the parser made
  globals of, and copies made with `util.table.deepcopy` taken for one table.
- **Hand checks**: 40 exact answers without a reference were checked by hand, and all were right.
- **Completion** (400 cases each, the word deleted or two characters left): listed 98.8 to 100%, first 47 to 56%, top
  five 69 to 81%, with two characters typed first 78 to 85%; a median of 0.8 ms (Biter Battles) and 5 ms (Factorio's
  2,079 files), an edit included.
- **Speed and memory**: the first answer in 120 to 150 ms (Biter Battles) and 0.9 s (Factorio's data), then a median
  of 0.001 ms per answer (p95 0.002 ms). The model holds 90 to 180 MB with every file parsed; code-model's runs over
  every position peak higher (940 MB on Factorio's 271,689) with its own reference and answers.
- **Crash runs**: 3,000 random words of each corpus, fixture and the stub, and 20,000 of 140 garbled copies (cut,
  shuffled, lines dropped, characters flipped): no crash or hang, at most 145 MB.

## Testing

```bash
swift test --filter CodeLuaModelTests
```

The tests write small projects to a temporary folder, with `^^` before the words they ask about, and read the stub:
scoping, globals, `require`, metatables, annotations, labels and long strings, completion and edits. CodeScanTests'
`luaLongBracketsEscapesAndOperators` covers the lexer.
